## A. Newly discovered P0: an empty but reachable NAS mount erases the logical work and bookmark

**Confirmed RED, not hypothetical:** on detached NAS/SMB/NFS, the underlying mountpoint may remain an empty, readable directory. In `main.go:scanWithProgress`, the root passes `canonical(root)`. A zero-result scan marks every source asset unavailable, then `catalogue.go:syncAutoCatalogueLocked` prunes old autogenerated works. Cascading foreign keys remove edition-level progress, even though the original user media may merely be disconnected. This exceeds the previously tested **missing-directory** case; `library_health.go` only probes shallow root availability.

**Isolation:** separate **quarantined test-only** [PR #66](https://github.com/russellstokes-ai/Archivist/pull/66) contains mirrored `server_mount_loss_rescan_test.go`, **no scanner production changes**. A synthetic indexed audiobook with a saved 143-second position is removed from a still-valid empty mountpoint, then rescanned. [Server CI #38908960336](https://github.com/russellstokes-ai/Archivist/actions/runs/38908960336) failed precisely:
```text
EMPTY MOUNT DATA LOSS: scanErr=<nil>, works=0,
former work present=0, saved playback bookmark=0
```
No real user file or server was touched. This **source-confirmed data-loss path requires P0 triage before any family/NAS acceptance**, and arguably before routine server scan testing with real data.

**Design constraint for Astra:** preserve historical work identity and saved progress when a source turns unavailable, even if individual physical assets are accurately marked unavailable. Distinguish accidental empty mount from intentional source deletion with explicit, journalled owner action; use source generation/mount identity or verified reconciliation semantics, not just `if total==0 return`, which misses partial mount/permission failures and might strand intentional clear operations. Cover 100→0, 100→1, nested mount loss, recovery, watched jobs, process restart, profile grants and migration. Do not touch either scanner/workflow without a separately approved exact scope. Don't merge failing PR #66 until safely GREEN.
