# Archivist 0.9.5 hardening review

## Status

Candidate branch: `review/0.9.5-test13-hardening`

Canonical UI baseline: `583ec8dde2936a2979648c010a4bd44cdc75e01d` (0.9.4 test-13)

Pinned UI reference: `ui-lock/0.9.5-test13-baseline`

This pass deliberately preserves the test-13 interface. Functional work must not simplify or restyle the locked UI.

## Approved UI changes

- branded launch keeps the Archivist mark and gains the ambient halo plus restrained one-shot motion;
- Fold Library source rail is 184dp with more readable Fold-only labels and divider;
- setup reuses the established pulse language and exposes scanner progress as:
  **Discover → Identify & group → Metadata & covers → Ready**;
- pulse intensity remains the approved test-13 value.

## Library/scanner hardening

- adding folders does not start heavy scanning;
- discovery remains one cancellable, generation-guarded job;
- discovery makes one authoritative SQLite catalogue replacement;
- metadata/cover enrichment checkpoints upsert only changed assets instead of repeatedly deleting/reinserting the catalogue;
- final enrichment is also an upsert;
- scanner progress remains shared across Shelf, Library and Settings;
- unresolved or coverless local works remain in maintenance/review and are not published to normal Shelf, Library, Atlas, recommendations or Android Auto;
- local Needs Attention is projected at work level, so a multi-file audiobook is reviewed once rather than once per chapter;
- root/messy audiobook grouping remains protected by the existing large-library/grouping regression suites.

## Metadata and covers

- normal automatic enrichment remains conservative;
- **Deep Scan** is a bounded per-work action, not a full-library rescan;
- Deep Scan can re-read likely companion audiobook files and regroup the work;
- provider results are review-first (`applyHighConfidence:false`) and are not applied until the user chooses a candidate and saves;
- when a recovered work contains multiple files, Save targets all recovered track URIs;
- accepted online cover artwork is cached app-private before the manual override is persisted;
- automatic provider covers continue to use the durable online cover cache;
- square audiobook edition artwork remains square for catalogue/Auto use;
- high-confidence portrait book artwork is maintained as a separate Living Book cover channel.

## Living Book / Now

- one Canvas renderer remains shared across phone and unfolded Fold;
- physical state remains explicit: closed → opening → open → turning → settling → closing;
- leaving Now preserves physical state rather than remounting/resetting it;
- stale animation callbacks remain generation-guarded;
- Pause during a page turn waits for the sheet to settle before closing;
- first ambient turn uses the shared first-turn delay;
- page turns use the shared 3-second timing contract;
- later ambient turns retain the longer rest interval;
- hinge open/close duration scales from the current hinge position, so interrupted reversals remain smooth;
- local playback and durable Now state continue to checkpoint during playback.

## Reader / comics

- reader chrome participates in layout rather than covering the top of a comic;
- fullscreen hides app chrome and native system bars; Android Back restores normal reader chrome;
- double-tap is reserved for speech/text focus after touch arbitration;
- comic fallback zoom remains tap-centered, with pinch zoom available;
- speech-bubble focus uses bounded analysis and cancels safely on resize/scroll/pinch;
- page-turn drag/velocity arbitration remains protected by regression tests.

## Atlas, Stats, Profile and Rewards

- Atlas ring is data-driven from real Format / Publication Year / Genre counts;
- constellation, inspector, Universe Stats and selection animation remain intact;
- Profile/Rewards and persistent avatar/level halo remain part of the locked UI;
- progression already reduces passive-library-import influence so adding a small library does not dominate levels;
- Reader Stats hierarchy remains locked.

## Android Auto

- `MediaLibraryService` + Media3 session;
- Android Auto discovery descriptor;
- legacy browser/search compatibility intent;
- media-button receiver;
- speech audio attributes and audio-focus/headphone safety;

- browse/search pagination;
- audiobook cover/author/book metadata;
- resume and phone/car progress handoff;
- only publishable local catalogue works are exported to the car.

## Physical-device acceptance checklist

The APK should not be accepted until the following are exercised on a real Android device, including closed and unfolded Fold layouts:

1. Cold launch: splash duration, halo and no flash/blank frame.
2. Onboarding: add multiple folders and/or server, then sequential scanner emphasis.
3. Large local scan: UI remains responsive while progress advances.
4. Root-level multipart audiobook: appears once after identification.
5. Unresolved work: absent from finished Library; appears once in Needs Attention.
6. Deep Scan: only the selected work is scanned; candidate is not applied before Save.
7. Cover recovery: accepted cover survives offline/relaunch.
8. Shelf/Library: covers, source rail and Fold composition match the locked test-13 baseline plus approved rail change.
9. Living Book: smooth open, prompt first page, ~3s page turn, Pause closes only after an in-flight page settles, no phantom page after leaving/returning to Now.
10. Resume: force-close/relaunch retains audiobook position and reader page.
11. Comic reader: top page is unobscured, fullscreen icon works, double-tap bubble focus and pinch zoom behave cleanly.
12. Atlas: chart sectors reflect catalogue data and selected stats panel follows the tapped category.
13. Rewards: small import does not cause implausible level progression.
14. Android Auto: Archivist appears in launcher customization/browse list; cover, progress, resume and 15s controls work in a real car/head unit.
15. Light/dark accessibility: gold/teal halo language remains coherent and Reduced Motion suppresses decorative motion.

Physical-device acceptance is intentionally separate from source/CI acceptance.
